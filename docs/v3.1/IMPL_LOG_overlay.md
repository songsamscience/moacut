### 그리기
- 미리보기 `colorGL.ts` FS_L `uFrame`(0 이면 기존 식 그대로): 사각형 = 바깥 상자, `vQ = 꼭짓점 × Q` 로 Q 좌표를 받아 `frameAlpha` 와 같은 GLSL(부호 거리 · 바이트 반올림 · 얹기 섞기). 내용 uv 는 `(vQ − pad)/P` 에서 자르기 · 뒤집기 반영. `playback.ts` 는 `layerFrame` · `frameOuterPx` 를 넘기고 미리보기 상자(LayerHit)도 바깥 상자로.
- 출력 `exportPipeline.ts`: 테두리 · 둥글기 요소는 프레임 사각형 = `frameOuterPx`, P = Q(가장 큰 배율 기준 — 키 크기 프레임은 sendcmd scale 로 줄어 테두리도 같은 비율). 사진 = Q PNG 에 굽기. 영상 = `scale=P,YUV709,format=yuva420p,pad=Q(투명)` → `[마스크]format=gray,setpts` `alphamerge` → `[테두리]rgba→bt709 tv yuva420p,setpts` `overlay=0:0:format=yuv420`(yuva 유지 — 네이티브 ffmpeg 6.0 에서 먼저 확인) → 이후 hflip · rotate · lut · sendcmd scale · 주 화면 overlay 그대로. 가지에 trim 없음, 마스크 · 테두리 입력은 `-t 길이+1` 반복(영상보다 먼저 끝나지 않게). 상한(layerCaps) · 조각 나누기 그대로.

## 결정(명세와 다르거나 명세에 없던 것)

1. **여백 = 화면 짧은 변 × 4 %(가로 · 세로 같은 px)** — 명세 §3 의 식은 가로 4 % W · 세로 4 % H(16:9 1080p 에서 77 px · 43 px)인데, 작업 지시가 「여백이 화면 px 로 같게」라 짧은 변 기준(43 px · 43 px)으로 했다. 9:16 도 43 px.
2. **크기 단계를 누르면 칸 여백 유지** — 명세는 「scale 만」. 오른쪽 아래 30 % → 크게 50 % 를 scale 만 바꾸면 가운데 기준으로 커져 화면 밖으로 밀려서, 지금 칸(가운데 칸 제외)에 있으면 새 크기로 그 칸 자리를 다시 계산한다. 칸 밖이면 scale 만.
3. **테두리를 켜고 끄거나 두께를 바꿔도 칸 여백 유지** — 같은 까닭(테두리가 바깥쪽으로 두꺼워져 가장자리에 붙음). 키로 x · y 가 움직이는 요소는 그대로.
4. **크기 단계의 뜻 = 그린 상자 긴 변이 화면 짧은 변의 몇 %** — 영상 · 사진은 scale 그대로, 도형은 `scale = 단계 / max(w, h)`(기본 도형 30 % = scale 1 이 「보통」). 명세 「도형 w·h 가 아니라 scale」을 지키면서 세 종류의 「보통」이 같은 크기가 되게.
5. **테두리 바깥 모서리 반지름 = r + min(b, r)** — r = 0 이면 바깥도 각지고(부호 거리 그대로 늘리면 b 만큼 둥글어짐), r ≥ b 면 동심원(두께 일정), 그 사이는 연속. **테두리 얹기 알파 = ring/(1 − c)** — 테두리를 내용 위에 「얹기」로 섞으면(출력 overlay) 안쪽 경계 화소가 c + ring(1 − c) 로 비어 틈이 생겨서. 단위 시험에 「틈 없음」 두 가지.
6. **영상 줄 고정 + 고른 블록 드러내기** — 명세대로 줄 높이 Δ 만큼 스크롤을 옮긴다(줄이 줄 때는 브라우저가 DOM 을 바꾸며 스크롤을 먼저 깎으므로 마지막 스크롤 값 + Δ). 그런데 1366×768 의 타임라인 스크롤 칸은 약 187 px 라 행이 2~3개가 되면 위 행이 눈금 밑으로 가 방금 올린 블록이 안 보였다 → **고른 블록이 반 넘게 가려졌을 때만** 그만큼 내려 보이게(이때만 영상 줄이 그만큼 내려감). 디자인 검토 거리: 행이 많을 때 위 행이 가려지는 것 자체(캡처 `ov-02a-1366-dark-pip-asis.png`).
7. **두께 기준 = 가장 큰 크기** — `width × 짧은 변` 은 가장 큰 크기 배율(키에 크기가 있으면 키 최대 — 그때 `transform.scale` 은 화면에 안 쓰이므로)일 때의 두께, 프레임마다 내용 폭 비율만큼. 키가 없으면 늘 정확히 그 두께(작업 지시 「키프레임으로 크기가 바뀌면 테두리 두께도 같은 비율로」 · 명세 「scale 과 무관」 둘 다 만족 — 크기 단계로 바꾼 정지 PIP 는 두께 그대로).
8. **aria 「겹침 k번째(앞에서)」는 겹치는 요소가 있을 때만** 붙인다(혼자면 늘 1번째라 소음).
9. **줄 머리 두 줄** — 92 px 열에 아이콘 15 + 「화면 위」 ≈ 37 + `+` 20 + 눈 20 + 간격이 들어가지 않아 이름이 「화.」로 잘렸다(실제 캡처). 행이 있으면 아이콘 · 이름 · `+` / 눈(오른쪽), 빈 줄(26 px)은 아이콘을 빼고 이름 + `+` 한 줄. 단추 18 px.
10. **미리보기 상자 = 테두리 바깥까지** — 끌기 · 안내선 붙기가 보이는 가장자리 기준이 되게.
11. 머리 「화면 위에」 단추 · 보관함 카드 단추 아이콘 = `PictureInPicture2`(줄 머리와 같게).
12. 사진 빈 자리 순서는 명세에 영상 것만 있어 오른쪽 위부터 같은 방식으로 정함.

- **900 px 가로 넘침 92 px 는 원래 있던 것** — 타임라인 머리 단추 줄이 줄바꿈 없이 넘친다. 단추 글을 예전 「레이어」로 바꿔 재 보면 81 px, 「화면 위에」로 13 px 늘었다. 머리에 `overflow-x` 를 주면 「화면 위에」 메뉴가 잘려 고치지 않았다(머리 줄 배치는 디자인 몫).
- 고른 상자 이름표가 화면 아래 가장자리 근처에서 미리보기 틀에 잘린다(회전 손잡이가 있으면 이름표를 상자 아래로 보내는 기존 CSS). 오른쪽 아래 PIP 가 기본이 되며 늘 보이게 됨 — 디자인 검토 거리.
- 줄 머리 · 블록 터치(≤480) 손잡이 28 px 는 CSS 로만 확인(375 캡처), 실제 터치 끌기는 돌리지 않았다.
- 미리보기와 출력의 **주 영상 색 차**(이 시험 원본에서 배경 출력 25,45,58 / 미리보기 30,47,61)는 테두리와 무관한 기존 차이 — 시험은 각자 잰 배경과 비교하고 평균 차 한도에 그 몫을 남겼다.
- 4K(2160p) 테두리 출력은 돌리지 않았다(코드 경로는 같고 Q 는 P 보다 2·pad 크다). `zz-all-res` 는 테두리 없이 통과.
- playwright 의 HTML 끌기는 dragstart 를 가로챈 뒤 잠깐 기다리고 마지막에 1 px 더 움직여야 dragover 가 그 자리로 간다(시험 도우미에 적어 둠).
