**「발랄함」을 재는 법 — 에너지 지수 E**: 프리셋 10개를 기준 모집단으로 두고 다음 네 값을 z-점수로 바꿔 평균한다. (1) F0 퍼짐 st, (2) F0 범위 st, (3) 조음 속도, (4) 소리 크기 요동(유성 구간 틀 dB의 표준편차, 새로 더할 것). E = 0 이 프리셋 평균, +1 이면 프리셋 가운데 가장 발랄한 축에 가깝다. 바닥선 E ≥ −1.3, 상한 E ≤ +1.6.

### 1.4 10개가 서로 겹치지 않게 하는 기준

| 기준 | 값 | 비고 |
|---|---|---|
| 같은 성별 어느 두 목소리 사이 ECAPA 코사인(시험 글 A 16파일 평균 임베딩끼리) | ≤ T_d = min(0.65, 같은 성별 프리셋끼리 코사인의 중앙값) | **T_d 는 0단계에서 프리셋 10×10 행렬을 재서 확정**(아직 없음). 같은 목소리 쌍 평균이 0.71~0.83 이므로 그보다 뚜렷이 낮아야 함 |

## 2. 외국인 말투 고치기

### 2.1 원인 가설과 확인 방법

| # | 가설 | 어떻게 확인(측정 설계) | 참이면 쓰는 수단 |
|---|---|---|---|
| H1 | 스타일 벡터(ttl)가 영어권 화자에서 나와 **억양(피치 곡선)**까지 옮긴다 — 내용어마다 강세처럼 피치가 크게 오르내리고, 문장 끝 「~요.」의 하강이 약함 | 프리셋 10개 × 비교 문장 + A 로 (a) 문장 끝 300 ms F0 기울기(st/s), (b) 어절당 F0 봉우리 수 · 크기, (c) F0 범위 st 를 재고 **원어민 기준(§2.4)** 분포와 비교. 프리셋마다 값이 다르면 ttl 이 원인 | 프리셋 선택 · 섞기(원어민 분포에 가까운 프리셋을 뼈대로) |
| H2 | **리듬**(음절 길이 들쭉날쭉)이 영어식 — 한국어는 음절 길이가 고른데 dp 스타일이 강세박자 리듬을 만든다 | ttl 을 M4(남) · F4(여)로 고정하고 **dp 만 프리셋 10개로 바꿔** 합성 → 음절 길이 nPVI · 변동계수(CV)를 잰다(정렬은 `torchaudio.pipelines.MMS_FA` + uroman, 또는 whisper 단어 시각). dp 에 따라 nPVI 가 바뀌면 dp 가 리듬을 쥐고 있음 | **dp 를 ttl 과 따로** 고른다 — 리듬이 가장 한국어다운 dp 를 같은 성별 5개가 공유해도 됨(리듬은 정체성이 아님) |
| H3 | **빠르기**가 빠르고 쉼이 짧아 「외국인이 외워 읽는」 느낌 | 프리셋 조음 속도 5.8~7.7 음절/초를 원어민 낭독 기준 분포와 비교. speed 0.90 · 0.95 · 1.00 · 1.05 로 같은 목소리를 만들어 §2.4 지표가 어떻게 움직이는지 | speed 를 목소리마다 0.95~1.08 로 낮춤 · 쉼 재설계(§2.3) |
| H4 | **쉼**: 조각 앞뒤 무음 0.46~0.59 s + 간격 0.3 s 로 문장 사이가 0.8 s 안팎으로 너무 길고, 쉼표 뒤는 짧아 리듬이 어색 | 문장 사이 총 무음(앞 조각 꼬리 + 간격 + 뒤 조각 머리) · 쉼표 뒤 쉼 길이를 재서 원어민 기준과 비교(`speech_span` 의 쉼 목록 확장) | 머리 · 꼬리 무음 다듬기 + 문장 0.5 s · 문단 0.9 s · 쉼표 0.2~0.35 s 목표 |
| H5 | **소리 단위**: 된소리(ㄲㄸㅃㅆㅉ) · ㅓ/ㅗ · 받침 ㄹ · 장음이 영어식으로 나온다 | 최소 대립쌍 문장 20개(예: 「불/뿔/풀」 「거리/고리」 「달/딸/탈」)를 만들어 whisper CER + 사용자 청음. 프리셋 사이 차이가 크면 스타일 영향, 모두 틀리면 모델 한계 | 가장 좋은 프리셋 선택(스타일로 조금), 나머지는 **고칠 수 없음 → 정직하게 말함** |
| H6 | **지금 섞기 방식**(10개 전부 · 남녀 교차 · 음수 가중치)이 억양을 뒤섞어 순수 프리셋보다 더 외국인처럼 들린다 | 0단계 청음에서 사용자가 **순수 프리셋 10개**와 **college-m/f** 를 같은 문장으로 듣고 「한국 사람 같음」 1~5점을 매긴다. 프리셋 ≥ 4, college < 3 이면 섞기가 범인 | D3 제약(같은 성별 2~3개 양수) |
| H7 | **문장 단위 합성**이 아니라 120자 조각이라 조각 안 문장 경계 억양이 뭉개진다 | 대본 창은 이미 문장 단위(한 줄 = 한 합성). 자막 마법사 묶음(120자)은 같은 글을 ① 120자 조각 ② 문장 단위로 만들어 §2.4 지표 · 사용자 청음 비교 | 문장 단위 합성을 기본으로(묶음은 길이만 모음) |

### 2.4 「원어민다움」 지표와 합격선

**기준 음성(보정용, 평가 전용 · 앱에 넣지 않음)**

| 묶음 | 출처 | 용도 |
|---|---|---|
| 원어민 낭독 ① | 사용자(교사) 본인이 비교 문장 + A 8문장을 읽어 녹음(2~3분) | 가장 가까운 「교실 말투」 기준. 동의 문제 없음 |
| 원어민 낭독 ② | Zeroth-Korean(OpenSLR 40, CC BY 4.0, 115명 낭독) 200문장 · KSS(여성 성우 낭독, CC BY-NC-SA 4.0) 200문장 | 분포(평균 · 퍼짐) 기준. 라이선스는 평가 전용으로만 |
| 외국인 말투 기준 | **없음**(무료 한국어 L2 말뭉치를 못 구함) → 사용자 청음 점수로 대신 | 0단계에서 프리셋 10개 + college 2개 = 12개를 같은 문장으로 듣고 「한국 사람 같음」 1~5점 |

**자동 지표(후보 → 값이 클수록 원어민 쪽)**

| 지표 | 계산 | 기대 민감도 |
|---|---|---|
| N1 운율 거리 | 문장별 [조음 속도, 음절 nPVI, F0 범위 st, 문장 끝 300 ms 기울기, 어절당 F0 봉우리 수, 쉼 비율] 6차원을 원어민 ② 분포로 표준화한 뒤 마할라노비스 거리(작을수록 좋음 → 부호 바꿔 점수화) | 높음(해석 쉬움) |
| N2 한국어 강제 받아쓰기 로그우도 | whisper-large-v3-turbo, language='ko' 고정, 토큰당 평균 로그확률 | 중간(음성 단위 어색함을 잡음) |
| N3 언어 판별 P(ko) | whisper 언어 판별 확률 | 낮음(거의 0.99로 포화 — 떨어지면 큰 문제의 경보로만) |
| N4 최소 대립쌍 CER | H5 문장 20개 | 중간(된소리 · 모음) |

**보정 절차**: 12개(프리셋 10 + college 2) × 사용자 점수(1~5)와 N1~N4 의 스피어만 상관을 구한다. 상관이 가장 높은 지표(또는 두 개의 평균)를 「원어민다움 점수 N」으로 쓴다. 상관이 모두 < 0.4 면 자동 지표를 믿지 말고 **청음 횟수를 늘리는 쪽**으로 절차를 바꾼다(§3.4).

**합격선**

| 단계 | 합격 |
|---|---|
| 자동(후보 걸러내기) | N ≥ 사용자가 4점 이상 준 프리셋들의 N 중앙값 **− 여유 0.25σ**(σ = 프리셋 12개 N 의 표준편차). 4점 이상 프리셋이 하나도 없으면 N ≥ 프리셋 상위 3개 평균 |
| 최종(사용자 청음) | 비교 문장 「한국 사람 같음」 ≥ 4/5 **그리고** 「자연스러움(기계음 아님)」 ≥ 4/5, 10개 가운데 8개 이상 통과. 긴 글 C 에서 「중간에 외국인 말투가 튀는 곳」 없음 |

**고칠 수 없는 한계가 드러났을 때 사용자에게 할 말(초안)**
> 「공개된 목소리 10개가 모두 영어권 화자에서 뽑힌 것으로 보여서, 섞기 · 빠르기 · 쉼으로는 억양을 어느 정도까지만 한국어답게 만들 수 있었습니다. 된소리 · 일부 모음의 발음 버릇은 모델 자체의 것이라 지금 엔진으로는 못 고칩니다. 더 가려면 (1) 한국어 화자 기준으로 만든 스타일(유료 Voice Builder) 또는 (2) 한국어 전용 무료 엔진으로 바꾸는 길뿐이며, 둘 다 이 작업 범위 밖입니다. 지금 목록은 10개 가운데 ○개가 청음 합격선을 넘었고, 못 넘은 것은 이름에 「(억양 조금 어색)」을 달아 두었습니다.」

### 4.3 「AI 로 만든 목소리」 고지 문구(VIRTUAL_NOTE 교체)
> 「이 목소리들은 Supertonic 3 의 공개 목소리를 섞어 만든 AI 음성이에요. 실제 사람의 녹음이나 목소리 복제가 아니에요. 영상에 쓸 때는 AI 음성임을 시청자에게 밝혀요.」

- 이름 옆 「AI」 표시 유지. 「대학생」 「원어민」 같은 말은 설명이 아니라 **성격 한 줄**(§1.2)에만, 그것도 청음 합격 뒤에만 쓴다.
- OpenRAIL-M (e)(기계 생성임을 밝힘)에 맞게 샘플 MP3 태그에도 「AI 생성 음성(Supertonic 3)」을 넣는다.

### 4.4 비교 듣기용 샘플을 앱에 넣는가 — **넣는다**

| 항목 | 결정 |
|---|---|
| 내용 | 비교 문장 1개 × 10 목소리, 엔진과 같은 씨앗(= 모델을 받은 뒤 같은 설정으로 만들면 같은 소리) |
| 형식 · 크기 | MP3 64 kbps 모노(Safari 포함 어디서나 재생) ≈ 40 KB × 10 = 0.4 MB. `public/voices/ko-m1.mp3` … + `voices.json`(sha256 · 씨앗 · 모델 판) |
| 까닭 | ① 모델 400 MB 를 받기 전에 골라 볼 수 있음 ② 목록 설명이 실제 소리와 맞는지 바로 확인 ③ 같은 씨앗 결과의 sha 를 회귀 시험 기준으로 씀 |
| 아닌 것 | 긴 샘플 · 여러 문장은 넣지 않음(용량 · 유지비). 샘플은 미리 듣기 전용이고 합성엔 안 씀 |
| 반영 | 「들어 보기」 단추 = `<audio>` 재생, 한 번에 하나만 재생, 재생 중 카드에 표시. 오프라인(PWA) 캐시 목록에 포함 |
